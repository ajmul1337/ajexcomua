# AJEX catalog database

The catalog uses PostgreSQL 15+; it is not stored in browser memory or downloaded as a whole. `db/migrations/0001_catalog.sql` creates the product, normalized article, brand, category, supplier, warehouse/inventory, cross-number, and extensible vehicle-fitment tables. `db/migrations/0002_warehouse_sources.sql` adds per-warehouse supplier, source, connection, import-profile, and last-run fields. `warehouse_products` stores per-warehouse availability; `products.stock`, `warehouse_id`, and `supplier_id` remain the default/summary values requested for product records.

## Apply the schema

Set `DATABASE_URL` to the PostgreSQL connection string, then run:

```sh
pnpm db:migrate
```

The migrations enable PostgreSQL's `pg_trgm` extension for indexed product-name search. The article lookup stores a normalized value generated by the database: it trims input, removes whitespace and punctuation (including hyphens), and uppercases letters. Thus `ab-12 34` matches `AB1234`. A unique brand/article index prevents duplicate canonical articles within one brand.

## Runtime connection

- Local/server runtime: set `DATABASE_URL`.
- Cloudflare: bind a Cloudflare Hyperdrive connection as `HYPERDRIVE`; its `connectionString` is read only on the server. Keep database credentials out of `VITE_*` variables.
- Secret storage: set `AJEX_CREDENTIALS_KEY` to a base64-encoded random 32-byte key (for example, `openssl rand -base64 32`) in local environment variables or Cloudflare Worker secrets. It encrypts each warehouse's API key, login, and password with AES-GCM. Keep this key backed up securely; rotating it requires re-encrypting stored warehouse credentials.

The warehouse/source editor is under **Склады**; supplier contacts are under **Поставщики**. One supplier may own many warehouse records. Each warehouse keeps its own API/email/file source, price format, column mapping, delimiter, encoding, and active flag. Blank access fields preserve saved credentials, and the panel only receives a “saved” indicator. Header auto-detection helpers live in `src/lib/price-format.ts`; explicit header names saved for a warehouse take precedence over common Russian/Ukrainian/English column names.

`listAdminProducts` is a protected server function. It accepts a maximum page size of 100, filters by brand/category/warehouse/supplier/status, searches normalized articles and cross-numbers plus indexed product names, and sorts by article, price, or update time. It uses keyset cursors (`hasMore` / `nextCursor`) rather than loading all products or counting the whole catalog. Exact/prefix article lookups use B-tree indexes, cross-number lookups are indexed, and name search uses `pg_trgm`. The existing admin product section can consume this function without ever receiving the full catalog.

The schema uses `bigint` IDs and indexes on the high-volume join and lookup columns, so 5–10 million product rows and a much larger cross-number table do not require browser-side storage. Start with a single appropriately sized PostgreSQL instance; partitioning can be added later if measured query and write loads justify it. No TecDoc data or dependency is included.
